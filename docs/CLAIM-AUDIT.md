# Claim / Evidence Audit

For every claim this project makes about what it does, this table states the evidence type, the source, and the qualification a reader needs. See `docs/EXPERIMENT-CONTRACT.md` for the formal evidence-level taxonomy (`LIVE`, `PRECOMPUTED`, `SYNTHETIC`, `PUBLISHED`, `ILLUSTRATIVE`) and `docs/phase-7-deployability-hardening.md` for the new `LOCAL_CHARACTERIZATION` label.

| Claim | Evidence | Source | Qualification |
| --- | --- | --- | --- |
| A recurrent latent-state substrate can apply a shared transition repeatedly and produce a prediction from the final state | LIVE | `recurrent-latent-toy-v1`, `src/reasoning/recurrent-runner.py` | Tiny (hidden size 8), deterministically initialized, not trained. Not a claim about any published or production reasoning system. |
| Task `1,0,1,1` at budgets 1/2/4/8 predicts `2, 4, 4, 2` | LIVE | This repository's fixed seed `20260907`, verified in `docs/phase-7-baseline-evidence.md` | Reproducible under this exact seed/architecture only. Not evidence that more computation generally improves correctness. |
| Across additional seeds, this network is correct in only 3 of 20 seed×budget combinations | LOCAL_CHARACTERIZATION | `src/experiments/seed-characterization.js`, real local run recorded in `docs/phase-7-deployability-hardening.md` | Five seeds, one task, one architecture. Not a statistically powered study; a local characterization intended to show the canonical example is not representative, not to establish a rate. |
| HRM uses coupled hierarchical recurrent computation at two update cadences | PUBLISHED | Guan Wang et al., *Hierarchical Reasoning Model*, arXiv:2506.21734 | Describes the published architecture only; this repository does not reproduce it. |
| LatentForge's `hrm-inspired` mode runs a simplified local two-level (H/L) recurrence | LIVE | `hrm-inspired-hierarchical-recurrence-v1`, `src/reasoning/hrm-inspired-runner.py` | Untrained, no deep supervision, no adaptive computation time, no datasets or benchmarks. Explicitly "inspired by," never "a reproduction of," HRM. |
| BDH-CQ separates demonstration-conditioned recurrent memory (S) from query-specific latent workspace computation (H) | PUBLISHED | Björn Engdahl et al., *BDH-CQ: In-Context Learning with Recurrent Latent Reasoning*, arXiv:2608.09888 | The paper states exact dimensions and update rules are proprietary; this repository does not reproduce them. |
| LatentForge's `bdh-cq-inspired` mode runs a simplified local S/H recurrence with the same two-stage structure | LIVE | `bdh-cq-inspired-local-v1`, `src/reasoning/bdh-cq-inspired-runner.py` | Untrained, tiny fixed dimensions, no ARC evaluation, no candidate ranking, no trained 150M-parameter model. |
| The Node API now enqueues one job per experiment rather than spawning a process per request | VERIFIED (this phase) | `src/reasoning/worker-client.js`, `src/server/server.js`; measured before/after latency in `docs/phase-7-baseline-evidence.md` | Applies to this repository's implementation only. |
| The container image runs without a host Python/PyTorch install | VERIFIED | `Dockerfile`, `requirements.txt`; GitHub Actions run for commit `6c5f914` (`docker` job: success) | This development sandbox still has no `docker` binary — verification is via CI's real Linux runner, not this sandbox. The CI job builds the image, starts the container, and confirms `/health`/`/ready`/`/api/experiment` all respond. |
| CI runs tests, build, and a container smoke test on every push | VERIFIED | `.github/workflows/ci.yml`; GitHub Actions run for commit `6c5f914` (`test` and `docker` jobs: both success) | No CI runner is available in this development sandbox itself, but the workflow has been executed on GitHub Actions — see `HACKATHON_BLOCKERS.md` B11 for the failure this pass found and fixed (a genuine cross-platform path bug) before reaching this green state. |
| Latent state vectors are human-readable thoughts | NOT CLAIMED | — | Explicitly and repeatedly disclaimed throughout the UI and docs (`stateObservation.description` fields, `#live-now-title`/`#result-title` panels). |
| Latent reasoning is more efficient or cheaper than verbal chain-of-thought | NOT CLAIMED | — | No token-count baseline, no external LLM comparison exists anywhere in this repository. |
| More recurrent computation reliably improves accuracy | NOT CLAIMED — CONTRADICTED BY LOCAL DATA | Seed characterization above | The canonical example is itself non-monotonic (budget 8 is worse than budget 4), and the wider seed sweep shows most seeds never reach the correct answer at any budget. |

This table should be kept current: any new claim added to the README, blog, or UI should get a row here stating its evidence type before it ships.
